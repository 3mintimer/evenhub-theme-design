# Even v2.4.0 に合わせる実装リファレンス

基準日: 2026-10-28。スマートフォン側 WebView 用。色は実画面のサンプルから得た近似、寸法・フォント・エラー等の未観測状態は実装用の推奨値であり、公式仕様ではない。

## 色の役割

| CSS トークン | Bright / light | Dark | 根拠と用途 |
|---|---|---|---|
| `--even-bg` | `#EEEEEE` | `#232323` | 観測: ページ全体の地 |
| `--even-surface` | `#FFFFFF` | `#2E2E2E` | 観測: 設定グループ、ホームのカード |
| `--even-text` | `#232323` | `#EEEEEE` | 観測: 主ラベルと見出し |
| `--even-muted` | `#595959` | `#BDBDBD` | 観測近似: 右側の値、説明文 |
| `--even-disabled` | `#919191` | `#8F8F8F` | 観測近似: 無効な選択肢。情報本文には使わない |
| `--even-action` | `#232323` | `#EEEEEE` | 観測: 主要ボタンの地、オンのスイッチ |
| `--even-on-action` | `#FFFFFF` | `#232323` | 観測: 主要ボタン上の文字 |
| `--even-input` | `#E4E4E4` | `#1C1C1C` | 推奨: 面より沈める入力。ダーク検索欄とホームの沈んだ面を参考 |
| `--even-border` | `#D6D6D6` | `#464646` | 推奨: 意図して設ける区切り用。下部メニューの標準線には使わない |
| `--even-danger` | `#A12828` | `#FFA9A9` | 推奨: エラー文字。文言・アイコンを併用 |
| `--even-highlight` | `#FDF99E` | `#FDF99E` | 観測近似: Knowledge Base の選択、Health の要約 |
| `--even-on-highlight` | `#232323` | `#232323` | 観測: 黄色の上の文字。darkでも明るく反転しない |

画面地を light=`#FFFFFF`, dark=`#111111` と一律に決めると今回の設定画面から離れる。面と地の段差を保ち、既存アプリの別画面や更新版の実画面があれば目的に近い画面を優先する。

通常の設定・主要ボタンはモノトーン。追加確認した Knowledge Base では選択中のノードと詳細パネルの見出し、Health では歩数・睡眠等の要約欄に淡い黄色が使われていた。light / dark で同じ黄色＋濃い文字を維持する。`#FDF99E` はキャプチャの支配色からの近似で、既存ガイドのブランド黄色 `#FEF991` と同一の公式トークンだとは断定しない。

黄色は「選択中の対象」「重要な要約」を示す面として使い、すべてのメニューや主要ボタンを黄色に揃えない。面の上の文字までdark用の明るい色へ反転させない。今回の Health グラフはモノクロのドットや濃淡で表現され、有彩色の系列分けは確認されなかった。別の画面やエラー状態も無彩色だけだと一般化しない。グラス描画の明るい緑をスマートフォン画面全体のテーマに転用しない。

## 文字と寸法

実画面の比率を参考に、スマートフォン向けCSSの出発点を次のように置く。数値は実装上の推奨値であり、アプリ内部の論理寸法を取得したものではない。対象画面と利用できる幅に合わせて調整する。

| 役割 | 実装の出発点 |
|---|---|
| ページ左右余白 | 12〜16 px。サンプルは12 px |
| カード内左右余白 | 16 px |
| 設定行 | min-height 56 px。長文では高さを増やす |
| カード角丸 | 6〜8 px。サンプルは8 px |
| グループ間 | 24 px、見出しとの間8 px |
| ページ見出し | 18〜20 px / 400〜500 |
| 行ラベル・値 | 16 px / 400、line-height 1.4〜1.5 |
| 補助説明 | 13〜14 px / 400、line-height 1.5 |
| 主要ボタン | 高さ44 px以上、角丸6 px、16 px / 400〜500 |
| アイコン | 20〜24 px程度、タップ領域は44 px以上を目安にする |

実画面は通常の太さのサンセリフが中心。画像だけからフォント名は断定できない。独自フォントを使うなら、プロジェクトに正規に利用可能なファイルがある場合に限る。配布アプリからフォントを抜き出したり、同梱済みと仮定したりしない。サンプルはシステムサンセリフ＋言語に応じたCJKフォールバック候補を使う。日本語の字間は標準を基本にし、英字向けの負の字間を一律に強くかけない。

表示言語によるラベルの長さ、CJK、日付形式との分離は [localization.md](localization.md) を参照。System language の切替後も色と部品の意味を保ち、固定高へ翻訳を押し込まない。

## 部品ごとの合わせ方

- **ページ見出し**: 簡潔なタイトル。設定詳細では中央タイトル＋左の戻る矢印が観測された。WebView にも同等のナビが必要な場合だけ設ける。履歴がない画面へ飾りの戻るボタンを置かない。
- **設定グループ**: 小さめの角丸の平坦な面。行ごとに別カードへ分解せず、関連行をまとめる。観測例には強い影や行間の水平線がない。
- **行**: 左が項目、右が値と小さいシェブロン。右寄せ値は補助色。行全体を適切な button / link / label にし、文字だけが小さなクリック対象にならないようにする。
- **選択肢**: 選択は右端のチェックで示す。大きな有彩色の塗りや装飾的なバッジを常用しない。Web 実装では radio / checked 等の意味も持たせる。
- **スイッチ**: オン／オフの2値で、同じ形のつまみが左／右へスライドする。3状態や記号の入れ替えにはしない。短い移動アニメーションを付け、`prefers-reduced-motion` では動きを抑える。やや四角い小さな角丸のトラックとつまみで、オンは lightで濃い地＋明るいつまみ、darkで明るい地＋濃いつまみ。オフの配色と160msの時間値は実装用の推奨補完。ネイティブ checkbox / switch の意味と操作性を保持する。
- **主要操作**: 明暗が反転する塗りボタン。複数の主要色を競わせない。補助操作はテキストか控えめな面で扱う。
- **検索・入力**: 低い面、簡単なアウトラインの検索アイコン、短いプレースホルダー。入力の意味を placeholder だけに任せない。フォーカスは主文字色の輪郭で分かるようにする。
- **シート・ダイアログ**: Knowledge Base の下部詳細パネルは、通常面に黄色の選択見出しと補助色の本文を組み合わせていた。ほかのダイアログへは、用途に応じて同じ色の役割を引き継ぐ。
- **アイコン**: 細いモノクロのアウトラインを基本にする。主ナビや機能アイコンへ絵文字を代用しない。制作・状態・SVG／PNGの扱いは [menu-icons.md](menu-icons.md) を参照。

## CSS の取り込み

`assets/even-theme.css` のルート変数はページ全体へ適用される。コンポーネント規則は `.even-ui` 配下に限定している。`html` に `data-even-theme`、WebView のルートに `class="even-ui"` を付ける。既存テーマがあるなら変数だけを対応付ける。

```html
<html lang="ja" data-even-theme="light">
  <!-- dark を指定すると明示ダーク、属性なし / system ならメディアクエリ -->
  <body class="even-ui">...</body>
</html>
```

明示設定はアプリの既存経路から初回描画前に反映する。ローカルプレビューは設定を保存しない。UI サンプルの「システム」は OS / ブラウザの `prefers-color-scheme` のことであり、Even 本体の Bright / Dark 設定との同期を実証するものではない。

CSS の `color-scheme` はブラウザ標準のフォーム等にも使われるが、カスタム部品の配色はトークンで対応する。[MDN: color-scheme](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/color-scheme) と [MDN: prefers-color-scheme](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-color-scheme) を参照。

## 下部メニューと safe area の境界

メニューと下側余白の間に細い水平線が現れる場合がある。border・影・背景の隙間など、発生元は対象アプリの実装で切り分ける。以下は意図しない線を防ぐWeb実装の方針であり、Even本体の内部実装を特定したものではない。

アプリ独自の下部メニューは、上下端を装飾の線や影で区切らないことを標準にする。メニュー本体と下側のsafe areaを、同じ要素の背景と `padding-bottom` で連続して描く。別の余白用要素、`hr`、1pxのスペーサーを挟まない。選択状態は個々の項目の面・アイコン・ラベルで示す。

同梱CSSの任意クラスは次の構造で使える。既存のナビゲーションがある場合は構造を置き換えず、該当する背景・余白・境界の規則だけを対応付ける。メニューが不要な画面へ新設したり、Even本体の下部タブを複製したりしない。

```html
<body class="even-ui">
  <div id="app" class="even-app-shell">
    <main class="even-page even-page--above-bottom-bar">...</main>
    <nav class="even-bottom-bar" aria-label="アプリメニュー">
      <!-- 既存のアプリ内リンク。現在位置は aria-current 等でも伝える -->
    </nav>
  </div>
</body>
```

- `.even-app-shell` は `100vh` をフォールバックに `min-height: 100dvh` とflex配置を使う。`html` のキャンバス、body、アプリルートを同じ `--even-bg` に揃え、短い画面でも既定の白地を下端に露出させない。
- `.even-bottom-bar` は `background: var(--even-bg)`、`border: 0`、`box-shadow: none`、区切り用疑似要素なし。余白は `calc(8px + env(safe-area-inset-bottom, 0px))` に相当する。同じsafe areaをページ側で重ねて足さないよう、`.even-page--above-bottom-bar` では下paddingを24pxに戻している。
- 既存の固定／sticky配置を使う場合も、safe areaを含む1枚の要素を下端まで描き、本文に必要な退避量を確保する。ホストがすでにWebViewの下端を内側に寄せていると確認できた場合だけ `--even-bottom-inset: 0px` 等で重複を避ける。未確認のまま固定値へ置き換えない。

線が残る場合は、メニュー、親要素、直前の本文、余白要素の**実際に適用されたスタイル**で、`border-top` / `border-bottom`、通常・insetの `box-shadow`、`::before` / `::after`、背景色・背景画像の差を確認する。フレームワークの区切り用クラスも対象にする。線を描いている指定を発生元で外し、全要素のborderやoutlineを一括で消さない。入力の枠、エラー、`:focus-visible` は保持する。負のmargin、微小なtranslate、上から線を覆う帯による隠蔽を対策にしない。

DOM内に発生元が見つからない場合は、WebView自身の描画とホスト側の外枠を切り分ける。ネイティブ側の線をCSSの修正済みと報告しない。

確認時は320 / 390 / 430 CSS px、light / dark、下側余白0と34px等の模擬値、各メニュー選択状態、短い本文とスクロール末尾を比較する。上端・下端・余白の継ぎ目を左右端まで拡大し、意図しない1px線・背景色の帯・隙間がないこと、キーボード操作のフォーカスが見えることを確認する。ブラウザの模擬余白は実機の `env()` やホストのinset処理の確認とは分ける。

`assets/theme-preview.html` の最下部にこの背景処理の見本があり、「下側余白の模擬値」を切り替えられる。外周の検証用フレーム線も除去した。見本の4ボタンは選択状態の比較用で、アプリ内の画面遷移は行わない。

## 最小限の受け入れ確認

- 同じ画面でlight / dark、明示light＋OS dark、明示dark＋OS light、自動モードのOS変更を確認する。テーマ変更が入力値や業務状態を消さないことも確かめる。
- 本文・値・補助説明は通常文字で4.5:1以上を目安にする。大きな文字は3:1以上。無効な部品の例外を通常情報へ広げない。[W3C: Contrast (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)
- 同じトーンを優先しつつ、視認性と操作可能性を損なう低コントラストや小さすぎる対象はコピーしない。
- ブラウザの見た目確認、Simulator、Even 内 WebView、物理 G2 は検証対象が異なる。CSS プレビューの合格を他へ拡大して報告しない。
